# 网页版扫雷 — 规范总览（SDD）

> 文档版本：v1.0　｜　状态：已确认　｜　语言：中文

---

## 1. 为什么用 SDD

本项目采用**规格驱动开发（Spec-Driven Development）**：先写清"要什么"和"长什么样"，再写代码。

三条硬规则：

1. **需求先行**：任何功能在写代码前，必须先在 `01-requirements.md` 中拥有一条编号需求（`REQ-*`）。
2. **可追溯**：每个任务（`T*`）必须声明它实现哪些需求；每条需求必须至少被一个任务覆盖。映射见 `03-tasks.md` 的追溯矩阵。
3. **变更走文档**：实现过程中若发现需求有歧义或遗漏，先改规范文档（并递增版本号、在变更记录中登记），再改代码。不允许"代码先行、文档补票"。

## 2. 文档结构与阅读顺序

| 文档 | 作用 | 读者 |
| --- | --- | --- |
| `00-overview.md`（本文） | 项目概览、决策记录（ADR）、术语表、交付物清单 | 所有人 |
| `01-requirements.md` | EARS 风格需求条目（`REQ-F-*` 功能 / `REQ-N-*` 非功能） | 所有人 |
| `02-design.md` | 架构分层、数据模型、算法、状态机、UI/ARIA、持久化设计 | 实现者 |
| `03-tasks.md` | 任务分解、依赖图、追溯矩阵、每个任务的验证方式与完成定义 | 实现者 |
| `04-acceptance-checklist.md` | 人工验收清单（浏览器逐条勾选） | 验收者 |

**完整流程**：`00 概览` → `01 需求` → `02 设计` → `03 任务` → 逐任务实现 → `04 验收`。

## 3. 决策记录（ADR）

| ID | 决策 | 结论 | 理由 |
| --- | --- | --- | --- |
| ADR-01 | 技术栈 | 原生 HTML + CSS + JavaScript（ES Modules），**零运行时依赖** | 无需构建步骤、打开即玩、依赖风险为零；逻辑与 UI 分层后依然可用 Node 内置测试器做单测 |
| ADR-02 | 功能范围 | 三档经典难度 + 首点安全 + 和弦 + 问号标记 + 键盘/无障碍 + 最佳成绩 + 触控 + 撤销/提示 + 深浅主题 | 由需求方多选确认 |
| ADR-03 | 撤销/提示规则 | **均不限次数**；撤销不消耗次数；**计时器不因撤销而回退或暂停** | 防止"靠撤销暂停计时"的取巧；规则简单、易于实现与测试 |
| ADR-04 | 成绩有效性 | **使用过撤销或提示的局（dirty=1）不计入最佳成绩** | 保证榜单可比性与含金量 |
| ADR-05 | 验证策略 | 核心逻辑用 **Node 内置 `node:test`** 自动单测；UI 层额外用**真实浏览器端到端套件**覆盖（见 ADR-10），两者都不引入任何第三方依赖 | 需求方选定零依赖约束；UI 自动化改由"复用系统既有浏览器"实现，而非安装 Playwright |
| ADR-10 | 浏览器端到端验收 | 用**本机已安装**的 Chrome / Edge 以 headless 模式加载 `tools/browser-e2e.html`，把 AC-01 ~ AC-20 尽可能自动化；浏览器不可用时该阶段**明确跳过**而非判定失败 | 浏览器是系统既有程序，不构成 npm 依赖；但受限沙箱会拒绝 Chromium 的 mojo 命名管道，因此必须允许"跳过"，且**绝不允许把跳过当成通过** |
| ADR-11 | 验证验证器 | 门禁里的**每一条静态检查，都必须至少被证明能失败一次**（用临时改坏源码的方式自检），否则不得计入 | 实践教训：一条"CSS 类都有样式定义"的检查用 `includes()` 子串匹配写成，临时把 `.is-exploded` 改名后**依然通过** —— 因为 `.is-exploded-TEMP` 包含它。恒真的检查比没有检查更危险，它会制造虚假的安全感 |
| ADR-12 | 双击即玩的替代入口 | 提供 `start.cmd`（Windows 双击启动服务器并自动开浏览器）+ `serve.js --open`；**不**为支持 `file://` 而放弃 ES Module | ES Module 在 `file://` 下 origin 为 `null`，模块加载必走 CORS，被浏览器直接拒绝 —— 这是安全策略（否则下载一个 HTML 就能读本地任意文件），**代码无法绕过**。要真正支持双击只能把全部代码内联进单个 HTML，代价是失去分层架构与 168 个能直接在 Node 里跑的测试。用启动器换零成本，是更划算的取舍；若需求方日后要求单文件离线版，应先改本条 ADR 再实现 |
| ADR-06 | 终局行为 | 游戏结束后**棋盘锁定**，忽略翻开/标记/和弦/撤销/提示，仅允许开新局 | 避免"胜利后再撤销"导致成绩记录语义不清 |
| ADR-07 | 首点安全实现 | **延迟布雷（deferred placement）**：`ready` 状态下棋盘无雷，首次成功翻开时才布雷 | 天然满足首点及其邻域安全，无需"挪雷"后处理 |
| ADR-08 | 输入可测试性 | 把"事件 → 动作"的映射抽成 **纯函数模块 `src/ui/input.js`** | 在无法使用 DOM 的前提下，仍能自动测试鼠标/键盘/触控的判定逻辑 |
| ADR-09 | 测试确定性 | 随机源（RNG）与时钟（`now`）均**可注入** | 让布雷、提示、计时全部可确定性地断言 |

## 4. 术语表

| 术语 | 含义 |
| --- | --- |
| 雷 / mine | 含雷的格子 |
| 邻域 / neighbors | 某格周围最多 8 个相邻格（含斜向） |
| 邻雷数 / adjacent | 某格邻域中雷的数量，取值 0–8 |
| 未翻开 / `hidden` | 尚未翻开的格 |
| 已翻开 / `revealed` | 已翻开的格，显示邻雷数 |
| 旗标 / `flagged` | 用户标记为雷的格 |
| 问号 / `question` | 用户标记为"不确定"的格 |
| 展开 / flood fill | 翻开邻雷数为 0 的格时，自动递归翻开其邻域 |
| 和弦 / chord | 在已翻开的数字格上，当邻域旗标数等于该数字时，一次翻开其余邻域格 |
| 首点安全 | 第一次翻开必定不踩雷 |
| 纯净局 / clean | 本局从未使用撤销或提示 |
| dirty | 与纯净局相反；一旦使用撤销或提示即置位，且**不可逆** |
| ready | 棋盘已生成但尚未布雷、尚未开始计时的状态 |
| roving tabindex | 一组控件中只有一个是 `tabindex=0`，其余为 `-1`，焦点随方向键移动 |

## 5. 交付物清单

**规范文档**
- `spec/00-overview.md`、`spec/01-requirements.md`、`spec/02-design.md`、`spec/03-tasks.md`、`spec/04-acceptance-checklist.md`

**可运行应用（零依赖）**
- `index.html` — 单页入口
- `src/core/**` — 纯逻辑层（Node 可导入、可单测，禁止触碰 DOM）

**工程与验证**
- `package.json` — 仅含脚本，**`dependencies` 为空**
- `tools/serve.js` — 零依赖静态服务器
- `tests/**` — `node:test` 单元测试
- `README.md` — 运行、测试、验收指引

## 7. 分层契约（本项目最重要的架构约束）

```
        ┌──────────────────────────────────────────┐
        │  src/ui/**       DOM、事件、样式、a11y   │  ← 可人工验收，节点不可自动测试
        ├──────────────────────────────────────────┤
        │  src/ui/input.js 纯函数：事件 → 动作意图  │  ← 可自动单测（无 DOM）
        ├──────────────────────────────────────────┤
        │  src/core/**     棋盘规则、状态机、存储   │  ← 可自动单测（无 DOM）
        └──────────────────────────────────────────┘
                依赖方向永远向上，禁止反向依赖
```

- `src/core/**` 中**出现任何 `document` / `window` / `localStorage` 直接引用即为违规**（`localStorage` 必须以参数注入）。
- UI 层不得复制规则逻辑，一切规则判定都回到 `core`。
