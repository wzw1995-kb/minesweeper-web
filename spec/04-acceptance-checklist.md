# 04 — 人工验收清单

> 版本：v1.0　｜　上游：`01-requirements.md`、`03-tasks.md`
>
> **适用场景**：本清单是 UI 层验收的**主路径**，覆盖浏览器中的端到端行为。
>
> **验证分三层**（见 `00-overview.md` 的 ADR-05 / ADR-10）：
> 1. **核心规则单测** —— `npm test`，168 个 `node:test` 用例，覆盖 `src/core/**`、
>    `src/ui/input.js`，以及 `src/ui/controller.js` 与 `src/ui/render.js` 中**不依赖 DOM 的纯函数部分**。
>    这部分**始终可执行**，是本项目验证的基础。
> 2. **人工走查** —— 即本清单，共 21 项。**这是 UI 层的验收主路径。**
> 3. **真实浏览器端到端**（可选）—— `npm run verify` 的第 7 阶段会加载 `tools/browser-e2e.html`，
>    用本机已装的 Chrome / Edge 把 AC-01 ~ AC-20 尽量自动化。需求方已选择不依赖它；
>    它仍然可用：能找到浏览器就给出逐项结论，找不到就明确标记"跳过"（跳过不等于通过）。
>    想跳过这一阶段，设置 `CHROME_PATH` 指向不存在的路径即可（或直接跑第 1~6 阶段）。
>
> **验收前置**
> 1. **Windows 用户：直接双击项目根目录的 `start.cmd`** —— 它会启动服务器并自动打开浏览器。
>    其它平台或想手动控制端口：在项目根目录执行 `npm run serve`（默认 <http://127.0.0.1:8123/>）。
> 2. **必须在浏览器地址栏输入该 `http://` 地址访问 —— 不要双击 `index.html` 文件。**
>    本应用使用 ES Module，浏览器在 `file://` 下会因同源策略直接拒绝执行它们，
>    页面会呈现为"难度下拉框为空、棋盘为空"。若发生这种情况，页面顶部现在会显示一条红色提示说明原因
>    （REQ-N-008）；没有看到提示却仍是空白，请检查控制台报错。
> 3. 按 `F12` 打开控制台并保持可见——**任一验收项执行期间控制台不得出现红色报错**。
> 4. 建议先执行一次 `localStorage.clear()` 以获得干净初始状态。

## AC-00　页面能正常启动（访问方式正确）

**这一项必须在其它所有项之前通过** —— 它不过，后面 20 项全部无从谈起。

**步骤**
1. 地址栏确认 URL 形如 `http://127.0.0.1:8123/`，**不是** `file:///E:/.../index.html`。
2. 观察页面顶部有没有红色提示条。
3. `F12` 打开控制台，看有没有红色报错。
4. 观察难度下拉框是否有三个选项、棋盘区域是否有格子。

**预期**
- 地址栏以 `http://` 开头。
- **没有**红色提示条。
- 控制台**没有**红色报错（尤其是 `Access to script at 'file://...' has been blocked by CORS policy`）。
- 难度下拉框有 **3 个**选项（初级 / 中级 / 高级）。
- 棋盘区域已经有格子（默认初级 = 9×9 = 81 个）。

**若不符合预期**
- 地址栏是 `file://` → 这是本次 AC-01 未通过的原因。请在项目根目录执行 `npm run serve`，
  然后访问 `http://127.0.0.1:8123/`。页面顶部的红色提示条也会告诉你这一点。
- 地址栏是 `http://` 但仍空白 → 页面顶部的红色提示条会给出捕获到的错误；把控制台的完整报错发给我。

**结果**：☑ 通过　☐ 不通过　　备注：需求方 2026-10-09 确认页面可正常打开并显示棋盘。控制台无红色报错一项未单独复核。

## AC-08　和弦展开（三种触发）

**前提**：需要构造一个"已翻开的数字格，其邻域旗标数等于该数字"的局面。可用以下方法快速构造：
> 用提示/翻开推进局面，找到某个数字格；把它邻域中**确定为雷**的格子插上旗，使旗标数等于该数字。

**步骤**（三种触发各测一次）
1. **双击**该数字格。
2. 在同一局面下（撤销后重做），在该格上**同时按下鼠标左键和右键**。
3. 聚焦该格（用方向键移动焦点到它），按 `Enter` 或 `Space`。

**预期**
- 三种方式都能触发和弦：该格邻域中**所有未插旗的格子被一次性翻开**。
- 若其中有雷 → 立即失败（正常结算）。
- 若旗标数**不等于**该数字 → 三种触发方式都**没有任何反应**（REQ-F-020）。
- 对邻雷数为 `0` 的已翻开格做和弦 → 没有反应。

**结果**：☐ 通过　☐ 不通过　　备注：

## AC-12　撤销

**步骤**
1. 开新局，记录下列逐步操作，每次操作后截图或用控制台记录棋盘快照：
   翻开一格 → 插一面旗 → 再翻开一格 → 触发一次零展开。
2. 连续点击"撤销"4 次，每一步都与记录比对。
3. 再点第 5 次撤销（此时应已回到开局）。
4. 观察计时器在整个撤销过程中的表现。
5. 观察撤销按钮的禁用态。

**预期**
- 每一步撤销都**精确复原**到操作前的棋盘与状态（旗标、问号、已翻开集合全部还原）。
- 撤销**不限次数**，可一路退回到开局（棋盘重新变为空白）。
- **计时器全程继续走，不回退、不暂停**（REQ-F-034）——这是本项目最重要的验收点。
- 撤回开局后继续翻开，仍然保证首点安全。
- 回到开局后再点撤销：无任何变化，且撤销按钮变为**禁用态**（REQ-F-033）。
- 一旦用过撤销，本局最终胜利**不会**刷新最佳成绩（见 AC-14）。

**结果**：☐ 通过　☐ 不通过　　备注：

## AC-14　最佳成绩与成绩有效性

**步骤**
1. 控制台执行 `localStorage.clear()`，刷新页面。确认最佳成绩显示 `--`。
2. 用初级难度打一局**干净**的胜利，**全程不使用撤销和提示**（可用 AC-10 的构造法）。
3. 观察最佳成绩显示，并在控制台执行
   `localStorage.getItem('minesweeper.bestTimes.v1')`。
4. 再打一局干净的胜利，故意用**更长时间**。
5. 再打一局胜利，但中途**使用一次撤销**（或提示）。

**预期**
- 步骤 2 后：最佳成绩显示该局用时（如 `37`），localStorage 中出现
  `{"beginner":37,...}` 形式的 JSON（REQ-F-041、042）。
- 步骤 4 后：更慢的成绩**不覆盖**更快记录，显示值不变（REQ-F-042）。
- 步骤 5 后：成绩**完全不变**，localStorage 内容不变（REQ-F-043）。
- 刷新页面后最佳成绩**依然显示**（持久化生效）。
- 切换到中级/高级，最佳成绩各自独立显示 `--` 或已记录值（REQ-F-044）。
- **降级测试**：控制台执行下面的代码后再做一次干净胜利，页面**不得报错**，且游戏可正常进行：
  ```js
  Object.defineProperty(window, 'localStorage', { get() { throw new Error('blocked'); } });
  ```
  （测完请刷新页面恢复。）

**结果**：☐ 通过　☐ 不通过　　备注：

## AC-15　键盘操作

## AC-16　无障碍语义

**步骤**
1. 控制台执行以下检查：
   ```js
   // a) 网格语义
   document.querySelectorAll('#board [role="gridcell"]').length;
   // b) roving tabindex：应恰好为 1
   document.querySelectorAll('#board .cell[tabindex="0"]').length;
   // c) 抽样查看 aria-label
   const c = document.querySelectorAll('#board .cell');
   [c[0], c[40], c[80]].map(e => e.getAttribute('aria-label'));
   // d) live 区域与计时器语义（REQ-F-052）
   [document.querySelector('#mine-count').getAttribute('role'),
    document.querySelector('#timer').getAttribute('role'),
    document.querySelector('#timer').closest('[aria-live]')?.id ?? '（不在 live 区域内）'];
   ```
2. 在任意格上插旗、翻格后，重新执行 (c)。
3. 用系统读屏（Windows 讲述人 / macOS VoiceOver）走查：读屏是否能读出格子位置与状态；插旗时剩余雷数的变化是否被播报；**计时器每秒跳动时不应被持续播报**。

**预期**
- (a) 数量等于棋盘格子总数。
- (b) 结果**恒为 1**（REQ-F-051）。

## AC-17　触控适配

> 需要触屏设备，或在 Chrome DevTools 中开启设备模拟（`Ctrl+Shift+M`）并启用触摸模拟。

## AC-18　响应式布局

**步骤**
1. 在桌面浏览器中把窗口从最宽逐步拖到很窄（约 360px 宽），或使用 DevTools 设备工具栏切换到 iPhone SE 尺寸。
2. 观察高级难度（30×16）棋盘的表现，并执行
   `document.documentElement.scrollWidth <= window.innerWidth`。

**预期**
- 棋盘**等比缩放**后完整可见，不被裁切（REQ-F-055）。
- 上面的表达式返回 `true`——**没有横向滚动条**。
- 状态栏元素在窄屏下合理换行，不重叠、不溢出。
- 初级（9 列）与中级（16 列）在手机上仍保持**舒适可点**的格子尺寸（初级 ≥ 30px，中级 ≥ 20px）。
- **高级（30 列）在 375px 宽的手机上会缩到约 11px/格**——这是"必须完整可见且不横向滚动"（REQ-F-055）的必然结果，属于**预期行为**而非缺陷。此时建议改用中级难度，或横屏 / 平板操作。
  > 这是一处明确的取舍：REQ-F-055 的"不横向滚动"优先于"格子足够大"。如需反过来（保证最小可点尺寸、允许横向滚动），需先修改 REQ-F-055 再改实现。

## AC-19　深浅主题与对比度
