# 网页版扫雷 · Minesweeper

一个以 **SDD（规格驱动开发）** 方式交付的网页版扫雷：先写规范文档，再按依赖关系拆解任务，逐任务实现并验证。

**零运行时依赖** —— 不需要 `npm install`，没有构建步骤，没有 `node_modules`。

---

## 快速开始

**Windows：直接双击项目根目录的 `start.cmd`** —— 它会启动本地服务器并自动用默认浏览器打开游戏。

或者用命令行：

```bash
npm run serve
```

然后打开 <http://127.0.0.1:8123/>。

> ⚠️ **不要双击 `index.html` 用 `file://` 打开。**
> 本应用使用 ES Module，浏览器在 `file://` 下（origin 为 `null`）会因同源策略**直接拒绝执行**它们 ——
> 表现是页面框架还在、但**难度下拉框为空、棋盘完全是空的**。
> 这是浏览器的安全策略（否则下载一个 HTML 就能读取你硬盘上的任意文件），**任何代码都绕不过去**。
> 从 v1.1 起，这种情况页面顶部会显示一条红色提示说明原因（REQ-N-008）；
> 但正确做法是用上面的任一方式启动本地服务器，再从 `http://` 访问。
>
> 想恢复"双击即玩"需要把所有代码内联进单个 HTML，会牺牲现有的分层与可单测架构 —— 见 `spec/00-overview.md` 的 ADR-12。

换端口，或启动后自动开浏览器：

```bash
node tools/serve.js --port 9000     # 指定端口
node tools/serve.js --open          # 启动后自动用默认浏览器打开
```

> **端口被占用时不会只说一句"启动失败"**：
> 如果该端口上已经跑着本应用，它会直接告诉你"服务器已经在运行了，打开这个地址"；
> 如果是被别的程序占用，它会自动顺延到下一个空闲端口（最多试 10 个）并**明确告知**换到了哪个端口。
>
> 因为全部是静态资源，用任何静态服务器（甚至 IDE 自带的）托管根目录也可以。
> 唯一要求是**通过 HTTP 访问**而不是 `file://`。

## 测试与质量门禁

```bash
npm test        # 168 个单元测试（node:test）
npm run verify  # 7 个阶段的质量门禁：语法 + 测试 + 零依赖 + 分层契约 + 离线 + 静态资源与样式 + 真实浏览器端到端
```

`npm run verify` 会依次检查（当前 **68 项全部通过**，另有 1 个阶段因环境限制被明确跳过）：

| # | 检查 | 对应需求 |
| --- | --- | --- |
| 1 | 全部 JS 文件语法（`node --check`） | — |
| 2 | 全部单元测试通过 | REQ-N-007 |
| 3 | `dependencies` / `devDependencies` 为空，且不存在 `node_modules` | REQ-N-001 |
| 4 | `src/core/**` 与 `src/ui/input.js` 不引用任何 DOM API，且能被 Node 直接 import | REQ-N-004 |
| 5 | 源码与页面中不含任何外部 URL | REQ-N-002 |
| 6 | 静态资源可达、元素 id 与 CSS 类契约、CSS 变量可解析与花括号配平、**ES Module 图可从 `index.html` 完整解析**、内联脚本语法、目录穿越被拒绝 | REQ-F-030、REQ-N-008 |
| 7 | **真实浏览器端到端**：用本机已装的 Chrome / Edge 跑 `tools/browser-e2e.html`，自动执行 AC-01 ~ AC-20 | REQ-F-001 ~ 060 |

> **第 7 阶段是可选阶段，且不会误报。** 它复用系统既有的浏览器，**不安装任何 npm 依赖**。
> 找不到浏览器、或浏览器无法启动时，它会明确输出"**跳过**"并说明原因 —— **跳过不代表通过**。
> 只想跑前 6 个阶段？把 `CHROME_PATH` 设成一个不存在的路径即可。

> **门禁自身的可信度**：每一条静态检查都被做过**破坏性自检**（临时改坏源码，确认它真的会失败）。
> 这一步抓到过两次"检查本身失效"（一次子串匹配导致恒真、一次正则对含大写的变量名失明），
> 规则记在 `spec/00-overview.md` 的 ADR-11。完整自检记录见 `spec/03-tasks.md` §4.3。

### UI 验收：以人工清单为主路径

UI 交互层的验收走 `spec/04-acceptance-checklist.md` 的 21 项清单（AC-00 ~ AC-20）：

```bash
npm run serve     # 打开 http://127.0.0.1:8123/
```

`tools/browser-e2e.html` 是**可选的加速器**：环境能启动 Chromium 时，它会自动跑完
AC-01 ~ AC-20 并给出逐项结论，你只需复核它未覆盖或存疑的条目（读屏体验、真实触屏手感、视觉观感）。
环境不支持时直接按清单人工走查即可，不影响交付。

> **受限环境提示**：默认的 `node --test` 会为每个测试文件 spawn 子进程并通过管道通信。
> 在禁止命名管道的沙箱中会报 `spawn EPERM`。因此 `npm test` 使用了
> `--test-isolation=none`（所有测试文件在同一进程内运行）。
> 如需标准隔离模式，用 `npm run test:isolated`。

## 怎么玩

| 操作 | 鼠标 | 键盘 | 触屏 |
| --- | --- | --- | --- |
| 翻开 | 左键单击 | `Enter` / `Space` | 单击 |
| 插旗 / 问号 | 右键单击（循环：无 → 🚩 → ? → 无） | `F` | 长按 500ms |
| 和弦展开 | 双击数字格，或左右键同时按 | `Enter` / `Space` 作用于已翻开格 | 开启「旗标模式」后单击已翻开格 |
| 移动焦点 | — | 方向键（边界处停止） | — |
| 撤销 | 点 ↶ | `U` | 点 ↶ |
| 提示 | 点 💡 | `H` | 点 💡 |
| 重新开始 | 点 🙂 | `R` | 点 🙂 |

**规则要点**

- **首点必定安全** —— 雷是延迟放置的，首次翻开时该格及其 8 邻域都不会有雷。
- **撤销与提示都不限次数**，但**计时器不会因撤销而回退或暂停**。
- **用过撤销或提示的局不计入最佳成绩**（保证榜单可比性），结算时会明确提示。
- 游戏结束后棋盘**锁定**，只能开新局。

**三档难度**：初级 9×9 / 10 雷　·　中级 16×16 / 40 雷　·　高级 30×16 / 99 雷

最佳成绩存在 `localStorage` 的 `minesweeper.bestTimes.v1`，主题选择存在 `minesweeper.theme.v1`。

## SDD 是怎么落到实处的

1. **需求先行**：任何功能在写代码前必须先在 `01-requirements.md` 里有一条编号需求（`REQ-*`）。
2. **可追溯**：每个任务声明它实现哪些需求；`03-tasks.md` 的追溯矩阵保证**无孤儿需求、无无主任务**。
3. **变更走文档**：实现中发现的歧义先改文档再改代码。本项目实际发生了 **4 次**：
   - `REQ-F-037` 精化 —— 提示候选要排除已插旗格，否则与 `REQ-F-010` 冲突会导致提示静默失效；
   - `REQ-F-052` 精化 —— 计时器移出 `aria-live` 区域，否则读屏会每秒播报；
   - `AC-18` 修订 —— 30 列的高级棋盘在 375px 手机上必然缩到约 11px/格，"不横向滚动"与"格子≥18px"不可兼得，明确取前者；
   - **新增 `REQ-N-008`** —— 需求方实测 AC-01 时以 `file://` 打开导致整页空白且无提示，据此补充"启动失败必须可见"的硬性要求。

   四次变更都登记在各自文档的变更记录表里。

4. **分层契约**（最关键的一条约束）：`src/core/**` 里出现 `document` / `window` / `localStorage` 直接引用即违规。
   这条约束由 `tools/verify.mjs` 自动把关，也是"零依赖前提下仍然有 168 个可自动执行的测试"的前提。

## 已知取舍与限制

- **UI 层有自动化覆盖，但可能被跳过**。`tools/browser-e2e.html` 用系统既有浏览器把
  AC-01 ~ AC-20 尽量自动化。但它**依赖环境能启动 Chromium**；无法启动时会明确跳过，
  此时 UI 的 DOM 部分就只剩 `spec/04-acceptance-checklist.md` 的人工验收。
  作为补偿，最容易出错的部分被抽成了**不依赖 DOM 的纯函数**并单测：`input.js`（事件→动作判定表）、
  `controller.js` 的 `closestCell` / `indexOfCell`（事件目标→格子索引）、`render.js` 的
  类名/内容/aria-label/文案、`theme.js` 的主题解析 —— 这些**始终有**单测（168 个用例）。
- **无法双击 `index.html` 直接玩**（ES Module + `file://` 同源策略）。替代方案见「快速开始」与 ADR-12。
- **高级难度在窄屏手机上格子会很小**（375px 宽约 11px/格）。这是"完整可见且不横向滚动"的必然结果，
  并非缺陷；如需反过来请在 `01-requirements.md` 中修改 `REQ-F-055`。
- **不支持自定义棋盘尺寸与雷数**、无联机、无音效、无排行榜（见 `01-requirements.md` §1.2 的范围声明）。

## 验收

UI 验收的**主路径**是 `spec/04-acceptance-checklist.md` 的 AC-00 ~ AC-20，逐条人工走查。

如果你的环境有 Chrome / Edge，可以先跑 `npm run verify`：第 7 阶段会把 AC-01 ~ AC-20 自动跑一遍，
把人工走查的范围收窄到它未覆盖或存疑的条目（读屏体验、真实触屏手感、视觉观感）。
这是可选的加速器，不是前置条件。

未通过项请记录「编号 + 复现步骤 + 实际结果 + 期望结果」，回到 `spec/03-tasks.md`
定位覆盖该需求的任务修复。
